# E84 Markdown Learning Output Skill

## Purpose

Export long learning outputs into Markdown files and keep Claude Code chat concise.

This skill exists because long study cards are hard to read in the chat box, while the chat box is still useful because file paths are clickable.

The final user experience should be:

```text
Full learning document -> saved as docs/learning/.../*.md
Claude Code chat -> short summary + clickable paths + next action
```

---

## When to Use

Use this skill when:

- the user asks to export learning output as Markdown,
- the output is a detailed file study card,
- the output is a module card,
- the output is a call-chain trace,
- the output is a contract audit,
- the output is a build/macro trace,
- the output is a debug playbook,
- the output is a lab conversion plan,
- the output is a learning review,
- the output would be too long to read comfortably in Claude Code chat.

```text

```

## Filename Rules

Use lowercase snake_case.

| Output type | Filename pattern |
|---|---|
| File study card | `<file_stem>_file_card.md` |
| Module study card | `<module>_module_card.md` |
| Call chain trace | `<event>_call_chain.md` |
| Contract audit | `<contract>_contract_audit.md` |
| Build/macro trace | `<macro>_build_macro_trace.md` |
| Debug playbook | `<symptom>_debug_playbook.md` |
| Lab conversion | `<mechanism>_lab_conversion.md` |
| Learning review | `<topic>_review.md` |

Examples:

```text
docs/learning/01_cm55_ipc/app_model_inference_file_card.md
docs/learning/01_cm55_ipc/cm33_cm55_inference_call_chain.md
docs/learning/01_cm55_ipc/shared_memory_contract_audit.md
docs/learning/02_ble_command/ping_command_call_chain.md
docs/learning/04_radar_parser/ld6002_parser_module_card.md
```

## Markdown Header Template

Every exported file must begin with:

```markdown
# <Title>

> Generated by: learning-tutor
> Skill: <source skill>
> Scope: read-only unless explicitly stated
> Source target: <file/module/contract/event>
> Output type: <file-card/module-card/call-chain/contract-audit/build-macro/debug/lab-conversion/review>

## Quick Summary

## Files Inspected

| File | Why inspected |
|---|---|

## How to Use This Document

- First read the Quick Summary.
- Then read the runtime chain or contract table.
- Finally answer checkpoint questions and complete the lab exercise.
```

---

## Chat Summary Format

After exporting, respond in chat with only:

```markdown
已导出学习文档：

- 文档：`docs/learning/.../<file>.md`
- 本次使用 skill：`<skill-name>`
- 阅读范围：
  - `path1`
  - `path2`
- 最重要结论：
  1. ...
  2. ...
  3. ...
- 下一步：...
```

Do not paste the full document into chat unless the user explicitly asks.

---

## Index Update

If exporting to `docs/learning/`, update or create:

```text
docs/learning/_index.md
```

Append one row:

```markdown
| Date | Topic | Type | Path | Next action |
|---|---|---|---|---|
```

If the user requested strictly read-only inspection, ask before updating `_index.md`. If the user asked to export Markdown, updating `_index.md` is allowed.

---

## Quality Rules

- The Markdown document should contain the full detailed result.
- The chat should contain only the compact summary.
- Keep file paths visible and clickable in chat.
- Do not use Markdown export to hide uncertainty.
- Mark unverified conclusions clearly.
- Do not modify production code.
- Exported learning docs under `docs/learning/` are allowed when the user asks for Markdown export.
