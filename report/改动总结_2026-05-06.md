# 改动总结

生成日期：2026-05-06

## 1. 本次重构目标

本次改动把原先比较混杂的 MIC 采集、测试导出、前处理和推理概念拆开，形成一条更清晰的 CM33/CM55 协作链路。

核心目标如下：

- `app_pdm_pcm` 只负责双 MIC PDM 到 PCM 采集，不再承担模型前处理职责。
- 原始 PDM/PCM 采集数据只留在 CM33 本地 SRAM，不放入 CM33/CM55 共享内存。
- CM33 新增正式音频前处理任务，把双通道 PCM 转成模型可用的量化 log-mel 特征。
- CM55 新增模型推理任务框架，从共享内存读取已经处理好的特征。
- `app_get_data` 只保留测试/自检用途，不再和正式推理命名混用。
- 保留测试导出能力，方便后续采集训练数据，但和正式业务链路解耦。

## 2. 当前整体架构

正式业务链路如下：

```text
双 MIC PDM
  ↓
app_pdm_pcm：PDM -> 双通道 PCM block
  ↓
app_audio_preprocess：双通道转单声道、滑窗、log-mel、量化
  ↓
shared/app_model_shared.h：只共享处理后的模型输入
  ↓
CM55 app_model_inference：读取特征并进入模型推理入口
  ↓
shared/app_model_shared.h：写回推理结果占位结构
  ↓
可选 app_model_result_monitor：CM33 侧调试观察结果
```

测试/采集链路如下：

```text
app_pdm_pcm
  ↓
APP_RUNTIME_MODE_MIC_SELF_TEST：app_get_data 做 MIC 采集链路自检

app_pdm_pcm + app_uart_radar
  ↓
APP_RUNTIME_MODE_CSV_EXPORT：app_csv_export 做训练数据采集导出
```

注意：`app_pdm_pcm` 内部只有一个 PDM block 队列。正式前处理、MIC 自检、CSV 导出都是该队列的消费者，同一时间只能启用一个。

## 3. 模块职责划分

### 3.1 app_pdm_pcm

位置：

- `proj_cm33_ns/source/app_pdm_pcm/app_pdm_pcm.c`
- `proj_cm33_ns/source/app_pdm_pcm/app_pdm_pcm.h`

职责：

- 初始化 PDM/PCM 硬件。
- 由 ISR 产生 10 ms 双通道 PCM block。
- 通过队列把 block 描述符交给唯一消费者。
- 维护 CM33 本地原始 PCM 缓冲 `recorded_data`。

关键约束：

- `recorded_data` 已从共享内存移出，现在在 CM33 本地 `.bss`。
- 构建检查中 `recorded_data` 地址为 `0x240d7e34`，不是 `m33_m55_shared` 区域。
- 原始 PCM 不应该再放入共享内存，避免干扰 CM55 模型输入协议。

### 3.2 app_audio_preprocess

位置：

- `proj_cm33_ns/source/app_audio_preprocess/app_audio_preprocess.c`
- `proj_cm33_ns/source/app_audio_preprocess/app_audio_preprocess.h`

职责：

- 从 `app_pdm_pcm_receive_block()` 接收 10 ms 双通道 PCM block。
- 检查 block 描述符、序号连续性和数据合法性。
- 执行正式模型输入前处理。
- 把处理后的量化特征发布到 `APP_MODEL_SHARED_REGION`。

当前前处理流程：

```text
双 MIC PCM
  ↓
双通道处理：左/右/平均/选优/固定延时求和
  ↓
16 kHz 单声道 PCM
  ↓
1 s 环形缓冲，默认 500 ms hop
  ↓
去直流
  ↓
RMS 归一化
  ↓
能量门限
  ↓
分帧 + 加窗
  ↓
功率谱
  ↓
Mel 滤波器组
  ↓
log
  ↓
特征归一化
  ↓
int8/uint8 量化
  ↓
共享内存输入槽
```

默认参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `window_ms` | 1000 | 模型输入窗口 1 s |
| `window_hop_ms` | 500 | 50% 重叠 |
| `frame_len_ms` | 25 | STFT 帧长 |
| `frame_hop_ms` | 10 | STFT 帧移 |
| `fft_size` | 512 | 当前最大 FFT 大小 |
| `mel_bin_count` | 40 | Mel bin 数 |
| `mel_low_hz` | 20 Hz | Mel 下限 |
| `mel_high_hz` | 7600 Hz | Mel 上限 |
| `energy_gate_threshold` | 1e-6 | 去直流后、归一化前能量门限 |
| `normalize_target_rms` | 0.10 | RMS 归一化目标 |
| `normalize_max_gain` | 20.0 | 最大增益限制 |
| `log_epsilon` | 1e-6 | log 防零偏置 |
| `feature_mean` | 0.0 | 特征均值，后续应替换为训练集统计值 |
| `feature_std` | 1.0 | 特征标准差，后续应替换为训练集统计值 |
| `quant_scale` | 0.03125 | 量化 scale |
| `quant_zero_point` | 0 | 量化 zero point |

重要说明：

- 这些参数都集中在 `app_audio_preprocess_config_t` 和默认宏中，不是写死在算法流程里。
- 后续训练参数变化时，应同步更新训练脚本、CM33 前处理配置、CM55 模型输入检查。
- 当前功率谱计算使用朴素 DFT，优点是便于先跑通端到端协议；如果实时性能不足，建议替换 `app_audio_preprocess_power_spectrum()` 为 CMSIS-DSP RFFT 或平台 NN/DSP 加速实现。

### 3.3 app_get_data

位置：

- `proj_cm33_ns/source/app_pdm_pcm/app_get_data.c`
- `proj_cm33_ns/source/app_pdm_pcm/app_get_data.h`

职责：

- 只用于 MIC 采集链路自检。
- 从 PDM block 队列取数，检查 block 合法性、序号连续性、幅值范围、均值和 checksum。

当前调整：

- 删除了旧的 `inference_task` / `APP_INFERENCE_*` 兼容命名。
- 公共接口只保留：
  - `app_get_data_test_task_init()`
  - `app_get_data_test_task()`
- `mic_data_test()` 已变为文件内静态函数。

约束：

- 该任务会消费 PDM block 队列，只能在 `APP_RUNTIME_MODE_MIC_SELF_TEST` 下启动。
- 正式业务模式下不要启动 `app_get_data`，否则会和 `app_audio_preprocess` 抢同一个队列。

### 3.4 app_model_shared

位置：

- `shared/app_model_shared.h`

职责：

- 定义 CM33/CM55 固定共享内存协议。
- 定义模型输入槽、结果槽、状态机、描述符和 payload 上限。

关键参数：

- 协议 magic：`APP_MODEL_SHARED_MAGIC = 0x4D464541`，含义为 `MFEA`。
- 协议版本：`APP_MODEL_SHARED_VERSION = 2`。
- 固定偏移：`APP_MODEL_SHARED_OFFSET_BYTES = 0x00008000`。
- 最大输入 payload：`64 * 100 = 6400` 字节。
- 最大结果分数数：`APP_MODEL_INFERENCE_MAX_SCORES = 16`。

共享内存划分：

```text
m33_m55_shared 起始地址
  ↓
前 32 KiB：保留给历史共享使用者，例如雷达帧缓冲
  ↓
APP_MODEL_SHARED_OFFSET_BYTES = 0x8000
  ↓
app_model_shared_region_t：音频模型输入和推理结果协议区
```

输入槽状态：

| 状态 | 写入方 | 含义 |
| --- | --- | --- |
| `APP_MODEL_SHARED_INPUT_EMPTY` | CM55 | 暂无可读输入，或上一帧已消费 |
| `APP_MODEL_SHARED_INPUT_WRITING` | CM33 | CM33 正在写描述符和 payload |
| `APP_MODEL_SHARED_INPUT_READY` | CM33 | CM33 已发布一帧输入，CM55 可读 |
| `APP_MODEL_SHARED_INPUT_READING` | CM55 | CM55 正在读取，CM33 不应覆盖 |

结果槽状态：

| 状态 | 写入方 | 含义 |
| --- | --- | --- |
| `APP_MODEL_SHARED_RESULT_EMPTY` | CM33 或初始化 | 暂无结果 |
| `APP_MODEL_SHARED_RESULT_WRITING` | CM55 | CM55 正在写结果 |
| `APP_MODEL_SHARED_RESULT_READY` | CM55 | CM55 已写入最新结果 |

当前结果槽采用“最新结果覆盖旧结果”的语义，适合调试观察。若未来业务必须可靠消费每一次结果，应扩展为双缓冲或结果队列。

### 3.5 app_model_inference

位置：

- `proj_cm55/source/app_model_inference/app_model_inference.c`
- `proj_cm55/source/app_model_inference/app_model_inference.h`

职责：

- CM55 侧创建 FreeRTOS 模型推理任务。
- 轮询共享内存输入槽。
- 当发现 `INPUT_READY` 时，把描述符和 payload 复制到 CM55 本地缓冲。
- 复制完成后释放输入槽，避免 CM33 被模型推理耗时阻塞。
- 调用占位推理入口。
- 写回结果槽。

当前占位行为：

- 模型尚未导入。
- 推理入口返回 `APP_MODEL_INFERENCE_STATUS_MODEL_NOT_READY`。
- `class_count = 0`。
- 如果打开 CM33 结果观察任务，看到 `MODEL_NOT_READY(2)` 是当前阶段的正常结果。

后续接模型时建议在 `app_model_inference_run_model()` 中补齐：

1. 模型初始化：加载模型、分配/绑定 tensor arena、解析输入输出 tensor。
2. 输入校验：确认 `mel_bin_count`、`time_bin_count`、`quant_type`、`quant_scale`、`zero_point` 与训练模型一致。
3. 输入填充：把共享 payload 复制到模型输入 tensor，必要时转置。
4. 推理执行：调用 NNLite、TFLM 或其它运行时。
5. 输出后处理：把类别数、分数和状态写入 `app_model_inference_result_t`。

### 3.6 app_model_result_monitor

位置：

- `proj_cm33_ns/source/app_model_result_monitor/app_model_result_monitor.c`
- `proj_cm33_ns/source/app_model_result_monitor/app_model_result_monitor.h`

职责：

- CM33 侧可选调试任务。
- 只观察 CM55 写回的结果槽。
- 不读取输入 payload。
- 不消费 PDM 队列。
- 不影响正式音频前处理。

开启方式：

```c
#define APP_MODEL_RESULT_MONITOR_ENABLE (1u)
```

默认值：

```c
#define APP_MODEL_RESULT_MONITOR_ENABLE (0u)
```

打开后，当前模型未导入阶段预期输出类似：

```text
[MODEL_RESULT] t_ms=..., input_seq=..., result_seq=..., status=MODEL_NOT_READY(2), class_count=0, infer_ms=...
```

## 4. CM33 main 运行模式

位置：

- `proj_cm33_ns/main.c`

当前运行模式由 `APP_RUNTIME_MODE` 控制。

| 模式 | 宏值 | 作用 |
| --- | --- | --- |
| `APP_RUNTIME_MODE_AUDIO_PREPROCESS` | 0 | 默认正式业务链路：PDM 采集 + 音频前处理 + CM55 推理 |
| `APP_RUNTIME_MODE_CSV_EXPORT` | 1 | 采集训练数据：MIC + 雷达导出 |
| `APP_RUNTIME_MODE_MIC_SELF_TEST` | 2 | MIC 采集自检 |

默认模式：

```c
#define APP_RUNTIME_MODE APP_RUNTIME_MODE_AUDIO_PREPROCESS
```

正式模式启动任务：

```text
CM33:
  app_pdm_pcm_task
  app_audio_preprocess_task
  可选 app_model_result_monitor_task

CM55:
  app_model_inference_task
```

CSV 导出模式启动任务：

```text
CM33:
  app_pdm_pcm_task
  app_uart_radar_task
  app_csv_export_task

CM55:
  启动后等待共享输入；因为 CM33 不发布正式特征，所以基本保持轮询等待
```

MIC 自检模式启动任务：

```text
CM33:
  app_pdm_pcm_task
  app_uart_radar_task
  可选 app_uart_radar_test_task
  app_get_data_test_task

CM55:
  启动后等待共享输入
```

## 5. CM55 工程变化

位置：

- `proj_cm55/Makefile`
- `proj_cm55/FreeRTOSConfig.h`
- `proj_cm55/deps/freertos.mtb`
- `proj_cm55/deps/assetlocks.json`
- `proj_cm55/main.c`

主要变化：

- CM55 工程新增 FreeRTOS 依赖。
- `main.c` 不再进入裸循环 deep sleep，而是创建 `app_model_inference_task` 并启动调度器。
- 当前 FreeRTOS 配置关闭 static allocation，避免必须实现 `vApplicationGetIdleTaskMemory()` 和 `vApplicationGetTimerTaskMemory()`。
- 当前 `configENABLE_MVE = 0`。后续如果模型使用 Helium/MVE 优化，需要同步打开并验证上下文保存、编译选项和性能。

## 8. 后续接模型建议

建议按以下顺序继续：

1. 明确模型输入 shape：
   - Mel bin 数
   - time bin 数
   - int8 还是 uint8
   - scale / zero point

2. 用训练配置回填 CM33 前处理参数：
   - `feature_mean`
   - `feature_std`
   - `quant_scale`
   - `quant_zero_point`
   - window/frame/mel 参数

3. 优化频谱计算：
   - 当前朴素 DFT 适合先验证协议。
   - 实时部署建议替换为 RFFT 或硬件/库加速。

4. 在 CM55 接入模型：
   - 增加模型文件或权重。
   - 增加 tensor arena。
   - 在 `app_model_inference_run_model()` 中实现真实推理。

5. 结果协议升级：
   - 如果模型输出类别数超过 16，修改 `APP_MODEL_INFERENCE_MAX_SCORES`。
   - 如果需要可靠消费每个结果，结果槽改为双缓冲或队列。

6. 上板联调：
   - 打开 `APP_MODEL_RESULT_MONITOR_ENABLE=1`。
   - 观察 UART 输出是否按 500 ms 左右更新。
   - 确认没有 `INVALID_INPUT`。
   - 确认 `input_seq` 和 `result_seq` 连续增长。

## 9. 常见注意点

- 不要同时启动 `app_audio_preprocess` 和 `app_get_data`，它们会抢同一个 PDM block 队列。
- 不要把 `recorded_data` 放回 `.cy_shared_socmem`。
- 修改共享协议时，要同步 CM33 和 CM55 两边代码。
- 如果 `APP_MODEL_SHARED_VERSION` 改变，CM33/CM55 必须同时更新。
- 如果共享内存变成 cacheable，需要实现 `APP_MODEL_SHARED_CLEAN_CACHE()` 和 `APP_MODEL_SHARED_INVALIDATE_CACHE()`。
- 当前结果观察任务默认关闭，正式业务不会打印 CM55 结果。
- 当前模型未导入时，`MODEL_NOT_READY` 是正确状态，不是错误。
